# 多账户私人空间

私人入口仍为 `/admin.html`，公开博客及 Markdown 发布流程不变。不开放自助注册。

## 使用

- 主账号名为 `owner`。升级后第一次登录使用原来的 `APP_PASSWORD`，成功后自动保存加盐密码哈希；以后以账号密码为准，修改环境变量不会覆盖已保存的密码。
- 在「设置 → 我的账号」修改密码；主账号还可展开「管理账号」创建、停用或重新启用普通账号。
- 账号为 3–32 位字母、数字、下划线或短横线；新密码至少 10 个字符。创建后初始密码只由管理员交给使用者，不在账号列表显示。
- 每个人的正念、健身、笔记、待办、习惯、打卡、文档、统计、搜索、导出均独立。管理员的管理权限不提供查看成员内容的接口。
- `STORAGE_QUOTA_BYTES` 按账号核算文档容量，Cloudflare 账户的实际存储用量仍为所有账号之和。
- 城市、外观、桌宠显示和音效在账号中保存。浏览器缓存按账号分开，旧浏览器偏好仅迁入 `owner`。
- 改密、退出登录和停用会使该账号所有旧会话失效。重新启用后必须重新登录，记录保留。
- 首版不包含邮箱找回或管理员重置成员密码。忘记密码时需由数据库维护者进行受控重置，不能通过更改 `APP_PASSWORD` 重置已经初始化的账号；不要删除用户或业务数据。

## 升级现有线上实例

此改动没有执行远端迁移或部署。上线前保留现有 D1 备份，并先执行账号迁移，再部署新版代码：

```sh
npm run backup
npm run db:accounts:remote
npm run deploy
```

`db:accounts:remote` 只执行 `migrations/0004_accounts.sql`，**只运行一次**，要求现有 `0001`–`0003` 已应用。不会清空记录、重新导入示例数据或移动 R2 文件。原记录全部归主账号，旧文档仍通过原对象键读取；新文件按 `users/<用户ID>/` 分区保存。

首次新建数据库需按顺序应用 `0001_init.sql`、可选的 `0002_seed.sql`、`0003_life_entries.sql`、`0004_accounts.sql`。不要使用旧版脚本遗漏后两项。

环境变量 `AUTH_SECRET` 必须存在，`APP_PASSWORD` 用于初始化主账号。没有配置密码不会再关闭认证。迁移后旧会话需要重新登录。

如果配置了 Git 自动部署，应在推送上线前完成迁移。启用多账户后，不要直接回滚到没有用户过滤的旧 Worker；旧版本会把所有记录视为共享数据。需要回滚时先关闭私人服务，再恢复匹配的备份和代码。

本地 `npm run dev` 自动迁移，`local_migrations` 记录已应用文件，重复启动不会重复 ALTER 或重新写入示例数据。

## 实现与验证

- 后端查询显式绑定当前会话的用户 ID，不信任客户端传入的数据归属。
- 习惯日志先验证所属习惯，列表按所属习惯筛选；文件下载先验证元数据归属，再读取 R2。
- 密码使用随机盐和 Web Crypto PBKDF2-SHA256（100,000 次，Cloudflare Web Crypto 支持的迭代上限），不存明文。会话使用签名 HttpOnly Cookie，并逐请求核对账号状态和会话版本。
- 登录按 IP 和账号限速；状态修改检查 Origin；私有 API 和文件响应禁止缓存。旧标签页提交携带账号标识，与当前 Cookie 不符时拒绝写入并刷新。

```sh
npm run test:all
npm run build
npm run dev
BASE_URL=http://127.0.0.1:8787 PLAYWRIGHT_MODULE=/path/to/playwright-core/index.mjs node tools/test-accounts-browser.mjs
```

账户接口测试使用临时数据库。浏览器测试仅应针对本地运行，会创建带 `test_` 前缀的账号，完成后停用并删除测试正念记录（软删除）；不会对线上账号执行操作。
